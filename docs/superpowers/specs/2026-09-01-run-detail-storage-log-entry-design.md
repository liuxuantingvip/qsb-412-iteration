# 运行详情新增入库日志交互原型设计

## 目标

在取数宝 412 迭代中，将“运行详情新增入库日志”的交互原型重构为与当前线上运行记录一致的下钻结构，并在运行记录详情中新增独立“入库日志”入口。

本次只建设可运行交互原型；PRD 与交互标注继续保持空状态，不代表生产接口或后端日志能力已经实现。

## 已确认设计原则

- 采用方案 A：完整保留线上“运行记录 → 运行详情 → 运行记录详情 → 日志”的层级。
- 线上页面是视觉和交互基线，原型不再使用当前单层“运行详情”抽屉。
- 组件库铁律：只能使用当前 412 工程已有的 Arco Design React 组件与 `@arco-design/web-react/icon` 图标。
- 不引入 Ant Design、Semi、其他组件库或跨组件库样式。
- 全局变量铁律：颜色、字号、间距、圆角、阴影、边框和状态色优先复用 `src/styles/global.less` 及现有页面变量；不得另建第二套全局变量或设计令牌。
- 设计风格铁律：保持 412 现有取数宝后台壳层、表格密度、状态标签、按钮等级和抽屉风格，不进行独立品牌化或视觉创新。
- 页面数据继续使用原型 mock，不将线上租户、店铺、计划或运行记录 ID 原样写入源码。

## 页面范围

### 保留

- 412 顶部需求入口“运行详情新增入库日志”。
- 电商取数宝后台壳层与“计划中心 / 运行记录”菜单状态。
- 当前运行记录列表的筛选、表格、分页和“运行详情”入口。
- PRD 空状态和交互标注空状态。

### 重构

- 将当前 `RunRecordDetailDrawer` 的单层信息卡重构为线上同层级的运行详情弹窗与运行记录详情抽屉。
- 补齐运行记录父子层级、连接器级运行结果和现有“查看日志”交互。
- 在运行记录详情中新增“入库日志”入口及入库日志抽屉。

### 不做

- 不修改生产取数宝前端。
- 不接入真实接口、真实日志、录屏或重试能力。
- 不补写 PRD 和交互标注。
- 不重构运行记录列表之外的自动重试策略页面。
- 不借本次需求改造线上已有交互范式。

## 信息架构与交互流程

1. 用户在运行记录列表点击某条记录的“运行详情”。
2. 页面打开居中的宽表弹窗“运行详情（计划名称）”。
3. 弹窗父行展示一次计划运行的汇总状态；展开后显示具体运行记录子行。
4. 失败父行在操作列展示“取数重试”和“入库重试”；原型点击后仅展示 Arco `Message` 反馈，不改变真实数据。
5. 用户点击子行“详情”，右侧打开“运行记录详情”抽屉，原运行详情弹窗保留在遮罩下方。
6. 运行记录详情展示基础信息、查看录屏、查看日志、入库日志和运行结果。
7. 运行结果先展示店铺汇总行；展开店铺后显示连接器级明细、阶段状态、异常原因、结果详情和重试入口。
8. 点击“查看日志”打开二级日志抽屉，展示与线上一致的运行日志查询和列表。
9. 点击“入库日志”打开同规格二级抽屉，展示该运行记录下的入库阶段日志。
10. 关闭二级日志抽屉后返回运行记录详情；关闭运行记录详情后返回运行详情弹窗；关闭运行详情弹窗后返回列表。

## 组件与视觉规格

### 运行详情弹窗

- 使用 Arco `Modal`，不使用 `Drawer`。
- 标题格式为“运行详情（计划名称）”。
- 宽度使用接近视口全宽的响应式值，左右保留 12px 至 16px 安全边距。
- 内容使用 Arco `Table`，横向滚动承载宽字段，不压缩至不可读宽度。
- 表格字段顺序与线上保持一致：展开列、计划名称、运行记录 ID、平台类型、平台名称、店铺名称、业务日期、最近运行开始时间、最近运行结束时间、耗时、取数执行、采集文件校验、数据入库、操作。
- 运行记录 ID 使用 Arco 图标和 `Message` 模拟复制反馈。
- 文本超长时使用 `ellipsis` 与 Arco `Tooltip`，不自造悬浮层。
- 底部使用 Arco `Pagination`，默认每页 20 条。

### 运行记录详情抽屉

- 使用 Arco `Drawer`，从右侧进入；桌面端固定宽度约 520px，窄视口使用 `calc(100vw - 24px)`，不得设置 760px 以上的最小宽度。
- 标题为“运行记录详情”，不再使用“执行信息”卡片作为唯一内容。
- 基础信息采用现有后台的紧凑标签—值排版，字段包括计划名称、计划类型、数据周期、平台类型、平台名称、机器人口令和运行记录 ID。
- 顶部操作使用 Arco `Button type="text"` 与 Arco 图标，顺序为“查看录屏 / 查看日志 / 入库日志”。
- “运行结果”区域使用三个 Arco `Select`：取数执行、采集文件校验、数据入库；配套“重置”和批量“重试”。
- 列表使用 Arco `Table` 的展开行：父行表示店铺汇总，子行表示连接器明细。
- 连接器子行状态旁展示具体异常原因；待运行状态不展示虚构失败原因。
- “结果详情”和“重试”使用文本按钮；重试操作只触发原型反馈。

## 第二轮视觉复查修复

### 复查结论

- 当前运行详情子表缺少与父表展开列等宽的占位，导致子记录从计划名称开始整体左移一列，并把“详情”推到不可见区域。
- 当前运行记录详情抽屉采用 `46vw + 760px min-width`，明显宽于线上约 500px 的信息层级，造成大面积留白并削弱底层 Modal 与上层 Drawer 的关系。
- 当前运行结果展开后，固定操作列遮挡状态字段；筛选区、表头和明细行没有共享一致的可视宽度。
- 当前入库日志表格的重要字段被压到视口外，缺少固定状态列、明确的长文本省略和一致的横向滚动区域。
- 当前展开按钮没有可读名称，文本操作的点击范围偏小。

### 已确认修复方案 A

- 运行详情 Modal 继续接近视口全宽，不改变线上信息架构。
- 子表最左侧增加与父表展开列一致的占位列；父子表使用同一组业务列宽，操作列均固定在右侧。
- 计划名称、店铺名称和运行记录 ID 使用单行省略；日期时间与状态不折行，避免表格行高被长文本撑开。
- 运行记录详情 Drawer 桌面端宽度固定为 520px；长字段独占一行，短字段使用双列，字段和值保持清晰间距。
- 运行结果筛选区允许按 Drawer 宽度自然换行；表格只使用一个横向滚动容器，操作列固定右侧且不遮挡状态。
- 查看日志和入库日志 Drawer 保持 830px；长内容使用 Arco `Tooltip`，入库状态固定右侧，分页固定在内容底部。
- 所有展开按钮补充 `aria-label`，图标按钮点击区域不小于 Arco 默认中号按钮高度。
- 修复只使用 Arco 组件、Arco 图标和当前 Less/全局变量，不引入新的视觉令牌。

### 运行记录详情批注修正

- “基础信息”和“运行结果”是分区标题，使用 Arco `@font-size-body-3`（14px）；不再使用正文级 `@font-size-body-1`（12px）。
- 运行记录详情 Drawer 默认及最小宽度为 520px，用户可拖动左侧把手向左扩展；最大宽度为当前视口宽度减 120px。
- 拖拽结束后保存宽度，重新打开同一原型时恢复上次宽度；窗口变窄后按最小/最大边界重新收敛。
- 拖拽把手使用当前 Arco 色彩变量与边框变量，支持 hover、拖拽中状态和键盘可读名称，不引入第三方拖拽组件。
- 运行结果筛选条件继续支持各 Select 自带的清除能力，移除额外“重置”按钮。
- 批量操作按钮由“重试”改为“重新运行”；未勾选店铺时禁用，点击后使用 Arco `Message` 反馈“已提交 N 条重新运行”。

### 查看日志抽屉

- 使用 Arco `Drawer`，宽度约 830px。
- 保留线上“查看日志”名称和交互，不改名为入库日志。
- 使用 Arco `Input.Search`、`Select`、`Table` 和 `Pagination`。
- 列表字段为时间、日志内容、日志级别。
- 提供正常日志、搜索无结果和加载态。

### 入库日志抽屉

- 与“查看日志”抽屉并列，而不是混入同一个 Tab。
- 使用相同 Drawer 宽度、标题区、筛选密度和分页样式，标题为“入库日志”。
- 顶部筛选包括关键字、店铺、连接器、入库状态和日志级别；均使用 Arco 组件。
- 列表字段为时间、店铺、连接器、数据表、入库状态、日志内容、日志级别。
- 状态覆盖成功、失败、运行中、待运行和部分无数据；状态样式复用现有 `StatusTag` 映射。
- 失败日志展示业务可理解的失败摘要；技术详情可通过 Tooltip 查看，但不在主表直接堆叠大段报错。
- 空状态使用 Arco `Empty`；加载使用 `Spin`；失败使用 Arco `Result` 或现有错误态样式，并提供“重新加载”。

## 状态与反馈

- 运行中、待运行、成功、成功（部分无数据）、运行失败、异常和入库失败必须在列表、弹窗和抽屉中保持同一套颜色映射。
- 状态不能只依赖颜色，必须同时显示文字。
- 复制、重试、重新加载等原型操作统一使用 Arco `Message` 反馈。
- 按钮禁用规则需要可见：未选择记录时批量重试禁用；不存在日志数据时不展示虚构内容。
- Modal、Drawer 关闭后清理当前选中记录、展开行和筛选状态，重新打开时回到默认状态。

## 数据模型边界

- 运行记录列表 mock 与运行详情 mock 通过稳定的原型 ID 关联。
- 运行详情父记录、子记录、店铺汇总、连接器结果、运行日志和入库日志分别建模，避免用一个扁平对象拼接所有层级。
- 仅保留当前交互需要的字段，不为未来接口预建通用日志平台模型。
- mock 中至少覆盖：全部成功、部分无数据、取数失败导致入库待运行、取数成功但入库失败四类状态。

## 可访问性与响应式

- 所有图标按钮必须有可读文本或 `aria-label`。
- 复制、关闭、展开和筛选控件支持键盘聚焦。
- Modal 与 Drawer 打开后遵循 Arco 默认焦点管理，不使用自定义遮罩或坐标交互破坏键盘路径。
- 1440px 及以上优先还原线上密度；较窄视口通过表格横向滚动和 Drawer 最小宽度保障可用，不把字段强行折成多行卡片。

## 验收标准

- 点击运行记录“运行详情”首先打开 Arco Modal，而不是当前单层 Drawer。
- Modal 字段、父子展开、状态、操作和分页与线上运行详情层级一致。
- Modal 父子记录的计划名称、ID、平台、店铺、日期、状态和操作列严格对齐；“详情”在 1280px 与 1960px 宽度下均可见。
- 子记录“详情”能打开 Arco Drawer，并保留底层 Modal。
- 运行记录详情 Drawer 在桌面端约 520px，基础信息无异常大留白，运行结果操作列不遮挡状态字段。
- 店铺行可展开到连接器级，成功、部分无数据和失败状态均可演示。
- “查看日志”和“入库日志”均能打开独立二级 Drawer，并可完成筛选、分页、空状态和关闭返回。
- 入库日志的时间、店铺、连接器、数据表、入库状态、日志内容和日志级别可通过固定列或同一横向滚动区域访问，不存在无提示裁切。
- 页面未引入 Ant Design、Semi 或其他组件库；新增组件全部来自 Arco 或当前工程已有组件。
- 新增样式复用当前全局变量和页面设计语言，没有新增第二套全局变量。
- PRD 与交互标注仍展示空状态。
- 自动化测试、类型检查和构建通过。
- 在 Codex 内嵌浏览器中，以相同视口并排对比线上截图与原型截图，复查结构、间距、字体、边框、圆角、遮罩和关键状态。
