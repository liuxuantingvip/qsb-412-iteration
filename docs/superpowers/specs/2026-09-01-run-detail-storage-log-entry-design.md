# 运行详情新增入库日志需求入口设计

## 目标

在取数宝 412 迭代中新增独立需求“运行详情新增入库日志”，先建立可访问的需求入口和交互原型基线，不提前确定入库日志在运行详情中的具体位置和展示结构。

## 范围

- 在 412 需求切换区新增“运行详情新增入库日志”入口。
- 该需求的交互原型默认进入现有“运行记录”页面。
- 复用现有运行记录和运行详情交互，用户可从运行记录继续打开运行详情。
- PRD 页展示统一的“该需求暂未编写 PRD”空状态。
- 交互标注抽屉展示空状态，不复用其他需求的标注。

## 交互流程

`412 需求切换 → 选择“运行详情新增入库日志” → 进入运行记录 → 查看现有运行详情`

用户在 PRD 和交互原型之间切换时，保持当前需求不变。PRD 为空状态，交互原型恢复到该需求的默认“运行记录”页面。

## 实现边界

- 新增独立需求 key，并同步需求类型、需求注册表和默认门户映射。
- 不新建独立运行记录或运行详情页面，避免复制已有交互。
- 不新增入库日志字段、Tab、模块、按钮或二级抽屉。
- 不修改现有运行记录、运行详情、PRD 内容和其他需求的交互标注。
- 所有页面和数据仍属于 412 可运行原型，不代表生产前后端能力已实现。

## 验收标准

- 412 需求切换区展示第六个需求“运行详情新增入库日志”。
- 直接访问对应 `requirement` URL 参数时，能正确识别并打开该需求。
- 选择“交互原型”后进入“运行记录”，现有运行详情仍可打开。
- 选择“PRD”后展示未编写空状态。
- 打开交互标注时展示空状态，不出现其他需求的标注。
- 需求注册测试、相关自动化测试和生产构建通过。
