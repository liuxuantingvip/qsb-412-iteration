# 概览中心数据异常板块设计

## 目标

第四行只回答一件事：当前统计周期发生了多少数据异常，异常处于哪个环节，用户接下来处理哪一条。

## 页面结构

第四行使用一张横向卡片，不再拆成两个互不连贯的板块。

### 左侧：数据异常率

- 标题：数据异常率。
- 主值：`异常数据表数 ÷ 当前统计周期产生的数据表总数`。
- 辅助值：`异常数据表：异常数 / 总数`。
- 对比：较上期变化，不使用“比昨日同时段”。
- 页面显示值必须由异常数和总数计算，不单独维护一个可能冲突的百分比。

### 右侧：异常明细

使用四个 Tab：

1. 登录异常
2. 取数执行异常
3. 入库异常
4. 入库校验异常

默认选中登录异常。每个 Tab 展示当前环节的异常明细，每行包含：

- 店铺
- 异常类型
- 异常原因
- 重试
- 查看

“重试”触发当前异常记录的重试动作；“查看”进入对应运行记录详情。切换 Tab 只切换明细，不改变左侧整体异常率。

## 数据口径

- 统计周期与页面标题旁的全局统计周期一致。
- 异常数据表按数据表去重计数，不能用失败计划次数替代。
- 登录或取数失败时可以没有文件，因此不展示“影响数据条数”。
- 不展示未定义的 SLA、影响价值、责任人或恢复时长。
- 较上期使用上一等长周期的异常率进行比较。

## 删除内容

- 删除 SLA 98% 及其差值。
- 删除“未成功交付构成”。
- 删除“影响最大的计划”。
- 删除影响数据量和恢复状态。

## 视觉

- 参考用户提供的横向卡片：左侧摘要约占 24%，右侧明细约占 76%。
- 左右之间使用竖向分隔线，不再嵌套多个卡片。
- Tab、明细和操作使用现有 Arco 组件语言；文案保持短句，不增加解释元信息。

## 验收

1. 异常率与异常数、总数计算一致。
2. 四个 Tab 均可切换并展示对应明细。
3. 每条明细可重试、可查看。
4. 页面不再出现 SLA、影响数据量、未成功交付构成和影响最大的计划。
5. 页面统计周期与异常板块口径一致。
