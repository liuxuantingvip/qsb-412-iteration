# 概览 PRD 重写设计

## 目标

在不改变现有 PRD 模板、章节顺序和页面样式的前提下，整体重写“优化取数宝概况”PRD，使研发和测试能够从背景、目标、范围、核心流程、业务规则和验收口径理解并评审当前原型。

## 文档模板

保留以下章节及现有双栏页面结构：

1. 版本信息
2. 需求背景
3. 目标
4. 需求范围
5. 用户故事
6. 用户场景与交互说明
7. 非功能要求
8. 本期不做

版本信息只保留现有 `V1.0`，不新增版本记录。不得新增独立章节或改变 PRD 页面样式。

## 内容主线

### 背景

说明当前问题不是缺少单项数据，而是账户价值、运行负载、机器人排期、数据交付和异常处置分散在不同页面，业务负责人和运营人员难以快速判断使用价值、运行健康度和待处理问题。

### 目标

围绕四项产品结果组织：

- 账户价值可感知：展示累计节省人力、资产使用和服务信息。
- 运行情况可判断：通过昨日、周、月指标及对比趋势识别变化。
- 机器人排期可检查：按日、周、月查看机器人计划分布、运行负载和计划详情。
- 数据异常可处置：查看完成率、异常率和四类异常明细，并执行重试或下钻运行记录。

### 范围

需求范围保持一个“前台-概况”P0 优化项，但功能点应完整概括账户价值、资产与公告、周期运行指标、机器人与运行数据视图、数据完成率和异常处置。

### 核心流程

核心流程写入现有“目标”和“用户场景与交互说明”，不新增模板章节：

`进入概览 → 选择昨日/周/月 → 查看运行指标及对比 → 切换机器人/运行数据视图 → 查看计划详情 → 检查数据完成率与异常率 → 重试异常或下钻运行记录`

## 原型映射

“用户场景与交互说明”按以下事项逐行说明展示内容、业务规则和验收口径：

1. 账户价值：累计节省人力、算法说明和到期时间。
2. 我的资产：店铺、连接器、云桌面、机器人的使用量/总量，以及增购入口。
3. 公告与资源中心：公告明细、更多公告、帮助文档和 SLA 服务手册。
4. 周期运行指标：昨日、周、月及计划运行次数、入库成功次数、入库数据量、取数失败次数。
5. 机器人视图：默认机器人视图，日/周采用 24 小时时间轴，月采用 7×6 自然月历。
6. 排期导航与全屏：禁止进入未来周期，全屏范围仅为当前机器人排期容器。
7. 计划卡片和 Tooltip：展示计划名、起止时间、耗时、运行次数、最新结果、错误码、涉及店铺和入库表；短卡片单行、较高卡片双行。
8. 运行数据视图：按当前周期展示总运行、取数失败、重试和入库成功趋势。
9. 数据完成与异常：展示完成率、异常率、分子/分母和同期变化。
10. 异常明细与处置：登录异常、取数执行异常、入库异常、入库校验异常；支持重试和查看运行记录。

## 用户故事

用户故事覆盖三类读者视角：

- 业务负责人：判断取数宝使用价值和周期运行结果。
- 运营人员：检查资产、机器人负载、计划排期和运行变化。
- 异常处理人员：识别异常环节、查看原因、重试或下钻定位。

## 删除的过期内容

删除或改写以下与原型不符的表述：

- 自定义周期。
- 页面内提交反馈和截图。
- 今日涉及店铺和平台交付分布。
- 固定 Figma 节点编号。
- “续期、增购本期不做”与原型入口相冲突的描述。
- 计划之间绝不重叠等原型没有承诺的规则。

## 边界

- PRD描述当前 412 可运行原型的产品规则，不宣称生产接口、真实数据或后端持久化已经实现。
- 不修改概览原型功能、Mock、路由、交互标注和其他需求 PRD。
- 不把测试实现、组件名称或 CSS 数值作为产品背景；技术约束只写入非功能要求和验收口径。

## 验收标准

- 八个模板章节及页面结构保持不变。
- PRD中的模块、指标、周期、视图、交互和跳转均能在当前概览原型中找到对应实现。
- 不再出现自定义周期、反馈、今日涉及店铺或平台交付等过期范围。
- 研发可据此识别功能边界和状态规则；测试可据此覆盖主流程、异常路径和跳转结果。
- PRD源码检查、自动化测试、生产构建和 5178 PRD 真页检查通过。
