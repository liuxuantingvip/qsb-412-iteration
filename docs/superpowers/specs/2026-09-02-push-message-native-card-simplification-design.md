# 推送消息原生卡片精简设计

> 本文为历次批注记录，模板布局与文案已有后续收口。当前实现和验收以 [消息推送模板收口](../../2026-09-02-push-message-template-review.md) 及当前可运行 PRD 为准；下文旧的公司名称、大号明细标题、分支元信息布局不再适用。

## 目标

精简消息效果预览中的重复信息，并确保飞书、企业微信、钉钉分别使用其群机器人 Webhook 官方支持的消息形式，不展示渠道无法实现的自定义布局。

## 已确认设计

- 卡片遵循“结论、上下文、业务数据、操作”四层结构，同一信息只展示一次。
- 预览新增内容类型：计划、店铺、数据表、数据监控视图。
- 计划、店铺、数据表在定时推送下支持“进度汇总、异常汇总”，在实时推送下支持“异常提醒、成功提醒”。
- 数据监控视图仅支持定时推送，保留“进度汇总、异常汇总”。进度汇总按推送时间截取完整看板并生成图片；异常汇总在相同截止时间和视图范围内仅保留异常数据后生成图片。
- 数据监控视图异常汇总没有异常数据时不生成图片、不发送群消息。
- 数据监控视图图片生成或上传失败时，不发送旧图片或空白图片；发送失败降级消息并直接附上对应数据监控视图 URL，同时在后台记录失败原因。
- 卡片头仅展示结果和租户名称；策略名称和时间合并为一处上下文；正文只展示该消息类型必需的数据；底部只保留详情入口。
- 飞书使用自定义机器人 `interactive` 交互式卡片：使用官方卡片头、文本/字段和按钮元素。
- 企业微信使用群机器人 `template_card` 模板卡片：文本消息按 `text_notice` 组织，数据监控图片按 `news_notice` 的图片结构组织。
- 钉钉使用自定义机器人 `actionCard`：正文按官方 Markdown 文本能力线性展示，数据监控图片使用 Markdown 图片，底部使用单按钮跳转；不模拟飞书式字段卡片或自定义指标宫格。
- 渠道不支持的排版必须降级为官方支持的线性文本，不追求三端像素一致。
- 产品类别以后端租户授权产品接口为唯一真值来源，仅展示授权已生效、尚未过期、未隐藏、授权执行状态为“授权完成”且推送策略支持的产品。前端不再按门户菜单名称推断；接口为空或失败时不回退全量，并阻止保存。
- 策略关联产品失效、下线或被取消授权后，保留策略和历史记录，自动停用并整行置灰，不展示失效标签；禁止编辑和启用，仅允许删除。整行悬停 Tooltip 为“该产品类别已失效，无法启用推送策略”。

## 四类消息的信息范围

- 计划进度汇总只展示日常计划、实时计划、回溯计划三类。日常计划按当天应运行计划数统计；实时计划总次数合并当天定时应执行次数与当天 00:00 至推送时间的手动实际执行次数，定时实际记录不重复计入；回溯计划按截至推送时间的实际次数统计。所有执行计数统一使用“次数”。
- 实时计划不再只取当天最新一次；成功、失败、运行中分别合计。未来定时执行和已到时间但未生成记录的执行在客户视角计入运行中，不新增“计划未按时启动”异常；手动执行不预估未来次数。示例为总次数 54、成功 37、失败 3、运行中 14。
- 消息区块不展示统计口径说明。三类计划去掉灰底、边框、圆角，使用留白分组；首行仅展示计划类型，次行统一展示总数、成功、失败、运行中。总数沿用“应执行／总次数／实际次数”标签，不在标题行重复。飞书使用等宽四列、小号彩色文本圆点，总数蓝点、成功绿点、失败红点、运行中橙点，仅成功绿色加粗、失败红色加粗。钉钉使用线性文本、单色文字圆点 `·`，仅成功和失败加粗；企微保留原生文字与单色文字圆点 `·`，不模拟未确认支持的富文本，不使用彩色圆球 Emoji。计划进度汇总的“需关注明细”标题改为“失败计划”，店铺、数据表和异常汇总标题保持原样。
- 三个渠道的计划进度汇总和异常汇总共享失败计划数据及条数。明细标题仅展示计划名称，不追加执行时间；描述展示计划类型（日常／实时／回溯）及本条执行的实际失败详情：取数执行失败展示错误码和具体错误详情，入库失败展示入库具体失败详情，入库校验失败保留独立的校验详情，不统一替换成同一种错误。错误码没有返回时不编造。实时计划异常提醒同样使用本条执行的实际错误。企微以 `quote_area.title/quote_text` 引用文本区承载明细，钉钉以正文 Markdown 段落列表承载；不复制飞书自定义卡片布局，也不因为布局差异漏掉内容。预览不代表真实群消息已验收。
- 数据监控图片必须来自数据监控模块内所选监控视图（店铺／数据表与日期的状态矩阵），保留该视图布局和筛选范围；不能另绘店铺统计卡片代替。当前两张独立绘制的示意图不符合要求，待获取用户指定视图截图后替换，尚未完成。
- 手动执行的实时计划不发送实时成功提醒，其成功结果进入定时进度汇总；执行失败仍可发送实时异常提醒。定时执行的实时计划仅在当天全部应执行次数均最终成功后发送一次成功提醒；汇总合并不改变成功提醒规则。
- 店铺进度汇总：租户、策略、统计时间、应关注店铺以及店铺下关联计划的完成、异常、运行中结果；不展示店铺等待状态。店铺按当天全部应执行计划的每次执行结果聚合，任一次失败为“存在异常”，没有失败但仍有执行尚未最终成功为“运行中”，全部最终成功为“全部完成”。
- “全部店铺”不取店铺管理全量，而取当天全部应执行计划关联的有效店铺并去重。推送时间只决定发送时点；当天晚于推送时间执行的计划及其店铺仍纳入，尚未最终成功时按店铺“运行中”展示。
- 数据表进度汇总：租户、策略、统计时间、数据表及其应交付店铺的完成、异常、运行中结果。
- 异常汇总：根据内容类型展示异常总数和计划/店铺/数据表定位明细。
- 异常提醒：租户、策略、计划、店铺、数据表、失败阶段、失败原因、发生时间、详情入口。
- 成功提醒：租户、策略、计划、店铺、数据表、完成时间、详情入口。
- 数据监控视图：租户、视图名称、统计范围、数据截止时间和完整或仅异常看板图片。

## 验收标准

- 四类消息均不存在标题、摘要、结果面板表达同一结论的情况。
- 三个渠道各自呈现官方支持的结构，不共用一个虚构的统一卡片布局。
- 推送方式、内容类型、消息类型和渠道能够按支持矩阵切换；数据监控视图不出现在实时推送中。
- TypeScript 检查、Vite 构建和 `git diff --check` 通过。

## 2026-09-02 计划定时汇总字段及官方能力复核

### 最新确认：三渠道统一计划定时汇总模板

明细展示最新全局规则：所有“需关注明细”标签改为“需关注”，保留已确认的失败计划、异常计划及异常明细标题。全部渠道明细按实际结果完整展示，不固定取前 N 条、不只展示第一条，不出现“另有 X 条”“等 X 条”或“更多异常”占位。仅达到实际渠道发送长度上限时以省略号结束被截断内容，详情入口和完整总数保留。当前预览未触发长度截断；店铺样例补全 5 条异常，与统计数对应，数据表维持 2 条。企微以原生普通文本区完整呈现，不塞入会单行截断的横向字段值；钉钉以正文段落列表呈现。此规则覆盖历史每类最多 10 条及剩余数量规则，生产发送长度裁剪仍需在真实发送链路落地验收。

全局公司名称规则（最新确认）：飞书、企微、钉钉的全部消息均删除公司/租户名称，覆盖计划、店铺、数据表的进度汇总、异常汇总、异常提醒、成功提醒，以及数据监控视图的进度、异常和图片失败降级消息。删除名称所在字段及空白占位，保留策略名称、实际业务对象名称、时间和入口；不修改租户权限及策略的数据隔离逻辑。此规则覆盖本文历史章节中所有“展示租户”的表述。

最新飞书进度视觉确认覆盖上一轮逐组横线方案：三类计划统计合并为一个浅灰统计面板。左侧为计划类型，右侧四等权指标列；每列标签在上、数字在下，相同状态纵向对齐，数字维持 20px，保留彩色小圆点。三组通过留白分开，不用组间横线。面板外为独立失败明细，标题维持正常 16px，底部元信息及区块间距收紧。采用飞书原生 column_set 的 grey 背景及多列布局映射；内层分栏承载计划类型与四项指标，字号、内边距与圆角由客户端实际呈现。未增加字段、总计或统计口径；企微、钉钉及飞书异常汇总不变。

后续飞书视觉批注：仅飞书计划进度/异常汇总增强卡片层次，不改变内容顺序。进度保持四列、标签与数字同组并对齐，数字 20px 突出；三类计划间用轻分隔。失败计划/异常计划仅为普通分区标题，采用 16px、600 字重、中性文字色，不再采用 26px 红色大标题。计划名称与具体错误分层，明细间使用分割线；元信息弱化、完整详情为原生主按钮。映射飞书分栏、文本字号/颜色、分割线和按钮组件，CSS 为原型近似而非发送内容；实际字号以客户端为准。企微、钉钉及其他内容类型不变。

本节最新规则覆盖下方历史调整中的不一致描述，仅影响计划进度汇总与异常汇总。三渠道共享内容组件和数据：进度三组统计（异常汇总省略）→ 大号加粗“失败计划／异常计划 · 数量 条” → 计划名称及实际错误详情 → 推送类型、策略名称、统计时间 → 完整详情入口。公司名称和顶部重复元信息取消。明细不预先截断、不显示“另有 X 条”；当前实际示例三条，六种预览均显示三条。原统计数字保持不变，跨类型计划数和次数的去重口径仍待确认，不通过样式统一改写。

飞书以原生文本标题、分栏和段落承载，钉钉以 ActionCard 的 Markdown 标题、段落及加粗承载；企微保留 text_notice，以 main_title.desc 承载进度普通文本，emphasis_content.title 承载明细标题，sub_title_text 承载明细，horizontal_content_list 三项承载底部字段。异常汇总仅省略统计辅助文本，其余与进度相同。未使用引用区重排或自定义富文本颜色。企微辅助信息建议 30 字、普通文本建议 112 字，当前示例超过建议长度；字段有效不等于客户端保证完整展示，真实群换行和长文本验收仍未完成，不把原型字号当官方固定字号。若实际发送达到渠道限制，保留总数并省略明细末尾。

本轮仅复核内容类型“计划”的进度汇总、异常汇总，不扩展店铺、数据表、监控图片及实时提醒。

企微异常汇总按最新批注将引用区标题合并为“异常计划 · 数量 条”，删除正文单列的重复异常计划总数；原 `sub_title_text` 的总数映射取消。字段保留、数量只展示一次。当前 `text_notice` 的引用标题及正文没有独立文字颜色配置，不以原型 CSS 冒充官方能力；如需对数量和失败详情标色，待确认是否切换支持警告色的 Markdown 消息。

后续确认保留模板卡片，不切换 Markdown，改为放大加粗：企微计划异常汇总的“异常计划 · 数量 条”使用原生关键数据标题，预览为 26px / 700 字重，最终字号由企微客户端决定；完整错误明细使用普通文本，不再使用引用区，也不重复显示数量。不额外配置自定义红色。普通文本可能超过官方建议的 112 字，仍需真实群长文本验收，不能以预览可见代替客户端展示验证。其他渠道及计划进度汇总保持不变。

最新批注仅调整企微计划异常汇总：删除公司名称和明细上方重复的推送类型/策略名称；底部用与统计时间相同的字段行依次展示“推送类型、策略名称、统计时间”。标题保留大号加粗“异常计划 · 数量 条”。展示本次实际明细全集，不预先固定只显示若干条，不显示“另有 X 条，进入门户查看全部”；仅当达到渠道可发送长度而需要截断时以省略号结束，详情入口保留。当前预览数据实际只有三条，因此标题显示三条并完整展示，不虚构额外十二条；该预览无截断。此规则优先于上方旧的三渠道统一头部和剩余条数描述，其他渠道不在本次批注范围内。

官方字段映射与边界：

企微计划进度汇总按最新批注改为总分结构：日常计划、实时计划、回溯计划三组统计在前，失败计划及明细紧随回溯计划，统计时间放在最后。统计与失败明细按此顺序合并到普通文本区 `sub_title_text`，时间仍使用底部字段行；不通过移动 `quote_area` 模拟官方模板不支持的区块顺序。此条覆盖下方旧的进度统计与引用区映射，其余字段、数量和渠道不变。长文本仍需真实客户端验收。

- 飞书：`msg_type=interactive`，标题/租户通过卡片头，正文通过文本及分栏组件，详情通过 URL 按钮承载。支持彩色文字和加粗；使用官方分栏，不将 CSS 发送给渠道。自定义机器人请求体最多 20 KB。
- 企微：`msgtype=template_card, card_type=text_notice`；`main_title` 承载标题及租户/策略，`quote_area.title/quote_text` 承载失败明细及剩余条数；进度统计三组及统计时间共四项，映射 `horizontal_content_list`，未超过六项上限；异常计划总数映射 `sub_title_text`。按模板原生顺序展示引用区和文本列表，不再模拟三个自由布局的指标组，不与 `emphasis_content` 混用。普通字段不支持任意 Markdown 加粗、颜色和四列布局。官方对二级文本建议不超过 26 字，当前长指标行与错误详情必须做客户端长文本验收，不把建议长度误写成接口硬上限。
- 钉钉：`msgtype=actionCard`；正文 `text` 承载标题、租户、策略、时间、统计和全部预览明细，`singleTitle/singleURL` 承载详情入口。`title` 是会话透出标题，卡片正文也需要写入可见标题。只使用官方列出的 Markdown 子集（标题、加粗、段落、列表、链接），不使用自定义字体颜色、CSS 圆点或指标宫格。
- 对齐的是业务字段和数据，不是像素级一致。原型验证不替代真实群 Webhook 发送、返回码、长文本和链接权限验收。
