# 概览中心交付问题下钻设计（已废弃）

> 2026-08-21：本方案包含未定义 SLA、影响数据量和无法成立的失败数据推算，已由 `2026-08-21-qsb-overview-data-anomaly-design.md` 取代，不再作为实现依据。

## 目标

将底部“交付质量”和“异常计划”从两个无关联的汇总板块，改成一条连续的定位链路：先解释未成功交付的构成，再定位受影响最大的计划。

## 信息架构

底部保持一行两栏，不新增页面行：

- 左侧 60%：“未成功交付构成”。展示所选周期内未成功交付的总次数与占计划运行次数比例，并按采集失败、入库失败、超时未完成、数据校验异常拆分。
- 右侧 40%：“影响最大的计划”。随左侧选中的问题类型联动，按影响次数从高到低展示计划名称、店铺或平台、影响次数、影响数据量和恢复状态。

## 交互

1. 左侧问题类型整行可点击，默认选中影响次数最高的“采集失败”。
2. 选中项使用浅蓝底、蓝色描边和明确的选中标识，不只依赖颜色表达。
3. 右侧标题显示当前筛选类型；点击计划行进入运行记录，并携带统计周期、问题类型、计划和店铺条件。
4. 右侧只展示影响最大的 3 条计划，“查看全部”进入保留统计周期与问题类型的运行记录。

## 数据口径

- 所选周期计划运行 28,765 次，成功入库 27,248 次，未成功交付 1,517 次，占 5.3%。
- 未成功交付构成：采集失败 602 次、入库失败 402 次、超时未完成 316 次、数据校验异常 197 次。
- 四类数量之和必须等于未成功交付总次数。

## 文案

- 删除“交付质量”“异常计划”“查看”等缺少定位含义的文案。
- 使用“未成功交付构成”“影响最大的计划”“影响 X 次”“查看全部”。
- 不再并列展示入库成功率、按期完成率、自动恢复率三个总数。

## 视觉

- 延续当前 Arco SaaS 页面白底、12px 圆角、轻阴影和 12/16px 字号体系。
- 左侧用可选择的横向占比条表达问题构成；右侧使用紧凑明细行，不再使用红点加文字的告警列表。
- 两个卡片等高、标题基线一致，信息密度与上方图表保持一致。

## 验收

1. 用户能从 94.7% 成功率继续看到其余 5.3% 的构成。
2. 点击任一问题类型后，右侧计划列表及标题同步变化。
3. 点击计划行或“查看全部”触发既有运行记录入口。
4. 页面不新增第五行，底部两卡等高且无溢出。
5. PRD、内容模型测试、TypeScript 构建和 5178 真页同步通过。
