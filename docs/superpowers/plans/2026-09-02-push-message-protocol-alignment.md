# 消息协议对齐 Implementation Plan

**Goal:** 修正企微监控宽图的消息形态，以三渠道 JSON 报文校对现有预览。

**Architecture:** 保留已确认的共享字段和三渠道视觉。企微监控使用独立 image 消息，随后发送仅包含标题、时间、视图、统计起点、策略和门户入口的 text_notice。纯函数根据预览同源数据生成协议报文，不连接 webhook，不发送消息。

**Tech Stack:** React、Arco、TypeScript、Node test。

**Spec:** 用户已确认上一轮“完整图片单独发送，配简短信息和门户入口；三渠道实际 JSON 反校预览”的方案。

## Constraints

- 仅修改 412 原型；不提交，不更换工作区，不接入真实发送。
- 不增加公司名称、重复时间、重复数量、“另有 X 条”。
- 不使用企微 news_notice 承载超宽监控图；图片 base64/md5 由发送端准备。
- 飞书保留官方分栏和图片 preview 能力；钉钉使用 ActionCard Markdown。
- 协议样例必须传入门户 URL 和已准备的渠道图片资源，不伪装成本地资产可直接发群。
