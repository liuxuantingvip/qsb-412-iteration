# 推送策略评审收口 Implementation Plan

**Goal:** 将用户逐项确认的九项规则同步到 412 PRD、原型与标注，不修改生产仓库，不提交代码。

**Architecture:** 保留现有 Arco 页面与 PRD 结构。增加可测试的策略规则模块；配置预览与历史共享消息渲染；模拟数据服务负责状态联动，外部服务变化通过标注示例或测试注入验证，不在业务页面新增调试按钮。

**Tech Stack:** React、TypeScript、Arco、Node tests、Mermaid。

**Spec:** 本任务此前逐项确认的九项决策为实施依据。

## 已确认规则

- 日常计划取当天最新运行结果，重试不增加数量，最终成功取入库及配置的校验结果；对象仅聚合自身交付，失败优先。
- 实时按策略、对象、消息类型、异常轮次或业务日期、渠道记录尝试；持续异常不重复，恢复再异常重新触发，新建/启用时已有异常提醒一次；失败不补发。
- 定时采用多个时间点，不使用开始结束时段。
- 监控查询前一日业务数据的当前交付状态，多视图一条消息，公共截止时间一致。
- 产品失效或自定义对象全部失效自动停用，恢复后自动恢复；手动停用不恢复，多种阻断条件同时存在时全部解除才恢复。
- 渠道停用保留关联，无可用渠道提示；全部删除自动停用，补充渠道后手动启用。
- 产品切换清空自定义选择，全部范围保留；候选按产品加载；查询失败不当失效。
- 实际表单支持局部查询重试和保存失败保留；标注复用实际组件。
- PRD 保留模板示例，策略预览读取未保存配置；历史保存原消息和渠道快照；门户按对象/范围定位，权限和删除不扩大范围。
